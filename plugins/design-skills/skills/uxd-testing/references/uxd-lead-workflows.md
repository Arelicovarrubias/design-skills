# UXD Lead Workflows

Use this reference as the source of truth for UXD Testing lead workflows around Lyssna testing demand, briefs, and sharing.

## Audience Split

Designer-facing work includes question QA, results-to-report synthesis, missing requirements checks, method guidance, and actual-customer branded testing rules.

UXD Testing lead work includes project-call briefs, sharing-session summaries, and weekly backlog triage.

## Project-Call Test Brief

Use this when turning project call notes into a decision-ready Lyssna test brief.

Return:

1. Test Overview
   - Team
   - Product or feature
   - Test type: first click, preference, five-second, prototype, survey, card sort, or tree test
   - Target participants
   - Decision deadline
2. Objective and Hypotheses
   - Primary objective
   - Secondary objectives
   - Hypothesis 1
   - Hypothesis 2
3. Scope and Constraints
   - In scope
   - Out of scope
   - Constraints, including timeline, tooling, branding, or legal
4. Required Assets Checklist
   - Figma link shared with UXD lead: Yes/No
   - Unbranded file ready: Yes/No
   - Questions drafted: Yes/No
   - Instructions drafted: Yes/No
   - Theme or flow confirmed: Yes/No
5. Risks and Mitigations
6. Follow-up 1:1 Agenda, 30 minutes
   - Open questions to resolve
   - Instruction clarity checks
   - Success criteria confirmation
   - Final ownership and due dates
7. Action Plan
   - Task
   - Owner
   - Due date
   - Status

Recommended inputs are stakeholders in the call, main user problem, research question, launch or decision date, and dependencies.

## Weekly Backlog Triage

Use this at the beginning of each week when reviewing the UXD testing backlog.

Return:

1. Weekly triage view
   - Tests to run this week
   - Tests to defer
   - Teams with zero-test backlog
2. Prioritization rationale
   - Explain tradeoffs across impact, urgency, readiness, and effort.
3. Capacity plan
   - Estimated load by UXD lead
   - Risks of over-allocation
   - Rebalancing suggestion
4. Outreach drafts
   - Message for teams with zero backlog
   - Message for teams asked to postpone
   - Message confirming test kickoff
5. Call agenda
   - 20-minute agenda for team backlog review call

Backlog fields to include are team, test name, priority, ready status, effort, deadline, and owner.

## Sharing-Session Summary

Use this to prepare content for LDA Testing Sharing Sessions or similar cross-team learning moments. The suggested cadence is once before every two-month sharing session.

Return:

1. One-page summary
   - What we tested
   - What we learned
   - What changed in design decisions
2. Cross-test insights
   - Repeated usability issues across teams
   - Repeated strengths across teams
   - Emerging risks to monitor next cycle
3. Reusable best practices
   - Writing better tasks
   - Running cleaner test setup
   - Reporting insights consistently
4. Next-cycle recommendations
   - Three experiments to run
   - Three process improvements
   - Three standards to enforce
5. Presentation script, 5 minutes
   - Opening
   - Three key messages
   - Closing ask

## Team Naming Convention

Use consistent naming in every test:

- Team
- Product area
- Test type
- Date in YYYY-MM-DD format
- Version, such as v1 or v2

Example: `ConnectPlatform_Nav-TreeTest_2026-04-28_v1`
