# Method Picker

Use this guide to choose the smallest useful UX process for the uncertainty, decision, and timeline.

## Decision Frame

Start by identifying:

- Decision: what the team needs to decide or move forward.
- Uncertainty: what could make the design direction wrong.
- Evidence: what is known, assumed, or missing.
- Constraint: timeline, access to users, team availability, launch pressure, compliance, or technical risk.
- Output: artifact needed to make progress.

## Uncertainty To Method

| Uncertainty | Best starting method | Output |
| --- | --- | --- |
| Problem is vague | Discovery framing | Problem statement, assumptions, success criteria |
| User/audience is unclear | Stakeholder interviews, data review, user interviews | Audience snapshot, needs, gaps |
| Value is uncertain | Concept test, fake-door test, preference probe | Value signals, decision recommendation |
| Workflow is complex | Journey map, service blueprint, task analysis | Current/future flow, pain points, opportunities |
| Usability is uncertain | Usability test, heuristic review, cognitive walkthrough | Findings, severity, fixes |
| Feedback is conflicting | Structured critique, decision matrix | Prioritized issues, decisions, unresolved tradeoffs |
| Team alignment is weak | Assumption mapping or alignment workshop | Shared risks, owners, next decisions |
| Engineering is blocked | Handoff review, state audit, acceptance criteria | Specs, edge cases, QA checklist |
| Launch quality is risky | Design QA, accessibility pass, content review | Launch blockers, fixes, residual risks |

## Timeline-Based Scaling

One day:

- Clarify the decision.
- Identify the riskiest assumption.
- Run expert review, quick data review, or structured stakeholder alignment.
- Produce a concise recommendation or checklist.

One week:

- Run discovery framing or a small validation study.
- Include 3-5 participants for directional usability or concept feedback when possible.
- Synthesize into themes, decisions, and next design changes.

Two to four weeks:

- Sequence discovery, prototype iteration, validation, and handoff.
- Create decision checkpoints so the process can stop early if evidence is strong.

## Method Selection Rules

- Do not recommend research when the real blocker is decision ownership.
- Do not recommend a workshop when one decision-maker can decide with clear evidence.
- Do not recommend usability testing before the target task and success criteria are clear.
- Do not recommend detailed design before the problem, audience, and constraints are stable enough.
- Use critique when the artifact exists and the team needs design-quality feedback.
- Use discovery when the ask is framed as a solution without a clear user problem.
- Use handoff review when the next failure mode is implementation ambiguity.
