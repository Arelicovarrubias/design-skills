# Visualization Picker

Use this when the user asks what visual to create, needs a canvas, or has messy information that would benefit from mapping.

## Pick The Visual

| Situation | Create | Why |
| --- | --- | --- |
| Management scope has unclear actors | Stakeholder map | Shows influence, ownership, and missing voices |
| Decision rights are unclear | DACI or RACI | Clarifies driver, approver, contributors, and informed groups |
| User experience unfolds over time | Journey map | Shows stages, actions, pain points, emotions, and opportunities |
| Internal systems shape the experience | Service blueprint | Connects user-facing moments to backstage teams, systems, and policies |
| Many assumptions are untested | Risk/confidence matrix | Identifies what to validate first |
| Many ideas compete | Impact-effort matrix | Makes tradeoffs visible |
| Strategy needs structure | Opportunity solution tree | Links outcome, opportunities, solutions, and experiments |
| Workshop stickies are messy | Affinity map | Clusters meaning and reveals themes |
| Options need comparison | Decision matrix | Applies criteria consistently |
| Follow-up needs sequencing | Now/next/later roadmap | Converts workshop output into action |

## Canvas Ingredients

Stakeholder map:

- Stakeholder or role.
- Influence.
- Impact.
- Current position.
- Needed from them.
- Engagement approach.

Journey map:

- Stage.
- User goal.
- User actions.
- Questions.
- Pain points.
- Emotion or confidence.
- Touchpoints.
- Opportunities.

Service blueprint:

- User actions.
- Frontstage interactions.
- Backstage actions.
- Systems and data.
- Policies or constraints.
- Failure points.
- Opportunities.

Assumption matrix:

- Assumption.
- Category: user, value, feasibility, viability, usability, operational.
- Evidence strength.
- Risk if wrong.
- Validation method.
- Owner.

Decision matrix:

- Options.
- Criteria.
- Weight if needed.
- Score.
- Tradeoffs.
- Recommendation.

## Creation Guidance

- Use a Markdown table for quick planning or synthesis.
- Use Mermaid for flows, decision paths, dependencies, or simple maps.
- Use FigJam, Miro, or Mural when participants need to collaborate live.
- Use Figma when the visual should connect to design artifacts.
- Use a spreadsheet when scoring, prioritization, or action tracking matters.

When recommending a visual, include the fields to create, the workshop moment where it belongs, and how it will be synthesized afterward.
