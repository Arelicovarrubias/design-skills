# Workshop Method Picker

Use this to choose workshop type, methodology, framework, tools, and activities.

## Workshop Types

| Need | Workshop type | Useful methods | Output |
| --- | --- | --- | --- |
| Scope is vague | Scope alignment | Decision framing, assumption mapping, stakeholder mapping | Shared scope, open questions, decision log |
| User journey is unclear | Journey mapping | Journey map, jobs to be done, pain-point mapping | Journey, moments that matter, opportunities |
| Process is complex | Service blueprint | Service design, frontstage/backstage mapping | Blueprint, dependencies, ownership gaps |
| Strategy feels broad | Opportunity framing | Opportunity solution tree, how might we, dot voting | Opportunity areas, prioritized bets |
| Risks are hidden | Assumption mapping | Risk/confidence matrix, premortem, five whys | Top assumptions, validation plan |
| Options compete | Prioritization | Impact-effort, RICE, MoSCoW, decision matrix | Ranked options, rationale |
| Team needs ideas | Ideation | Design studio, crazy 8s, how might we | Concept directions, selection rationale |
| Feedback is scattered | Critique or synthesis | Structured critique, affinity mapping | Themes, issues, recommended changes |
| Ownership is unclear | Decision workshop | DACI, RACI, stakeholder map | Owners, decision rights, next steps |
| Work needs closure | Retrospective or readout | Rose/thorn/bud, start/stop/continue | Lessons, actions, owners |

## Method Families

- Design Thinking: use for divergent/convergent discovery and ideation.
- Double Diamond: use to structure broad exploration into focused definition and delivery.
- Design Sprint: use when the team needs a compressed path from problem to tested concept.
- Lean UX: use when speed, assumptions, and iterative validation matter.
- Jobs To Be Done: use when motivation, progress, or switching behavior is unclear.
- Service Design: use when internal operations, systems, or handoffs shape the experience.
- Participatory Design: use when users or frontline teams should co-create solutions.

## Tool Choices

- FigJam: best for design-team workshops, Figma-connected work, visual canvases, and lightweight collaboration.
- Miro or Mural: best for large cross-functional workshops, templates, or mixed artifacts.
- Figma: best when workshop output connects directly to design artifacts.
- Slides: best for executive alignment, pre-reads, and readouts.
- Spreadsheet: best for prioritization, scoring, decisions, and action tracking.
- Teams or Zoom transcript: best for synthesis, quote capture, decision review, and follow-up.

## Selection Rules

- Start with the output, then choose the method.
- Do not use ideation before the team agrees on the problem.
- Do not use prioritization before criteria are clear.
- Do not use journey mapping when the real issue is decision ownership.
- Do not invite broad groups into synthesis before raw inputs are clustered.
- Use voting only after participants understand the criteria.
